## Confirmed defects versus unverified risks

Confirmed and corrected: reporting wrappers on writes; DeleteBy email/username mismatch; general scope substituted for personal assignments; invalid Dashboard scope returning reference metadata rather than an error; label seeds overwriting customized text; missing reader result silently converted to an empty report.

Confirmed but blocked: five report plugin scoped definitions/mappings absent. Their original SQL is not in the repo; do not synthesize replacements from names or invoke unscoped aggregates. Current Web.config and default staging bundle target different namespaces.

Unverified: SQL execution/binding, original operational administrator/creator semantics in the current target, deployed permissions/audit rights, mixed-role cross-surface operation consistency, correct required-report denominator, full Framework/IIS behavior, real-user lost/gained monthly rows, measured performance and exports. These are release gates, not claims of confirmed data loss or disclosure.

## Representative population and worklist evidence

`live_readonly.py` selects trunglc.kha, a numeric-taxcode enterprise-only account with exactly one explicit assignment, and a management account; it does not use nmdgio7a.dn as representative. It compares actual September 2026 monthly records, grouping exactly by the existing worklist output fields, and records lost/gained counts before/after assignment filtering. It uses prospective source SELECT expressions and TDS 7.0, without installing SQL or modifying authorization records. The connection attempt failed with TimeoutError; therefore **no replacement account identity or actual monthly totals are asserted**. Fixture expected populations are synthetic test specifications, not current-database observations.

The native fixture suite includes full admins with/without assignments; management with/without/multiple/duplicate grants; enterprise assigned/unassigned; mixed roles; empty scope; inactive/locked/deleted users and inactive/deleted enterprises; invalid mapping; unverified identity collisions; manipulated AllowProvince; assignment outside Dashboard industry; personal worklists; stable search paging; missing reports; scoped totals. Creator-only fallback is retained at record level, not expanded to enterprise-wide read/write authority. Operational reads mask other creators; the read-only ownership precondition verifies all rows and any file header affected by a creator-only write. This correction preserves original write parameter/audit/return contracts and closes the direct-ID ownership gap.
